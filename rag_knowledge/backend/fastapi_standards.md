# FastAPI Development Standards

## 1. Purpose

This document defines the FastAPI development standards for backend applications generated by the Agentic SDLC platform.

The Backend Agent must follow these standards when designing, generating, reviewing, testing, and modifying FastAPI applications.

---

# 2. FastAPI Version Standards

Use a currently supported FastAPI version.

The exact version must be defined in the project's dependency configuration.

Example:

```text
fastapi>=0.115,<1.0
```

Dependencies must be compatible with the selected Python version.

Do not use deprecated FastAPI features when supported alternatives exist.

---

# 3. FastAPI Project Structure

Recommended structure:

```text
app/
│
├── api/
│   ├── routes/
│   │   ├── projects.py
│   │   ├── users.py
│   │   └── jobs.py
│   │
│   └── dependencies.py
│
├── core/
│   ├── config.py
│   ├── security.py
│   └── logging.py
│
├── models/
├── schemas/
├── services/
├── repositories/
├── utils/
│
└── main.py
```

Maintain clear separation:

```text
API
 ↓
Service
 ↓
Repository
 ↓
Database
```

---

# 4. Application Initialization

FastAPI application initialization must be centralized.

Example:

```python
from fastapi import FastAPI

app = FastAPI(
    title="Project API",
    version="1.0.0",
)
```

Application configuration should not be scattered across multiple modules.

Use application lifespan management for startup and shutdown resources where appropriate.

---

# 5. Router Standards

Use `APIRouter` for endpoint organization.

Example:

```python
from fastapi import APIRouter

router = APIRouter(
    prefix="/projects",
    tags=["Projects"],
)
```

Routes should be grouped by business domain.

Example:

```text
/api/v1/projects
/api/v1/users
/api/v1/jobs
```

Avoid placing all endpoints inside `main.py`.

---

# 6. API Versioning

Production APIs should use explicit versioning.

Recommended:

```text
/api/v1/projects
/api/v1/users
/api/v1/jobs
```

Versioning should be consistent across the application.

Breaking API changes should result in a new API version where required.

---

# 7. Route Standards

FastAPI routes must remain thin.

Example:

```python
@router.post(
    "/",
    response_model=ProjectResponse,
)
async def create_project(
    request: ProjectCreate,
    service: ProjectService = Depends(get_project_service),
):
    return await service.create_project(request)
```

Routes should primarily handle:

```text
Request
 ↓
Validation
 ↓
Dependency Resolution
 ↓
Service Call
 ↓
Response
```

Do not place complex business logic inside routes.

---

# 8. HTTP Method Standards

Use HTTP methods according to their intended semantics.

```text
GET     → Retrieve
POST    → Create
PUT     → Replace
PATCH   → Partial Update
DELETE  → Delete
```

Do not use `POST` for every operation without a valid reason.

---

# 9. Path Standards

Use resource-oriented paths.

Good:

```text
GET    /api/v1/projects
GET    /api/v1/projects/{project_id}
POST   /api/v1/projects
PATCH  /api/v1/projects/{project_id}
DELETE /api/v1/projects/{project_id}
```

Avoid action-heavy paths when standard REST semantics are sufficient.

Bad:

```text
POST /api/v1/createProject
POST /api/v1/deleteProject
```

---

# 10. Request Schema Standards

Use Pydantic models for structured request bodies.

Example:

```python
from pydantic import BaseModel, Field


class ProjectCreate(BaseModel):
    name: str = Field(min_length=1, max_length=100)
    description: str | None = Field(
        default=None,
        max_length=1000,
    )
```

Validate:

* Required fields
* Data types
* Length
* Format
* Allowed values
* Business constraints

Never blindly trust client input.

---

# 11. Path and Query Parameter Validation

Validate path and query parameters.

Example:

```python
from typing import Annotated

from fastapi import Path


async def get_project(
    project_id: Annotated[str, Path(min_length=1)]
):
    ...
```

Query parameters should also define appropriate constraints.

Example:

```python
from fastapi import Query


async def list_projects(
    page: int = Query(default=1, ge=1),
    page_size: int = Query(default=20, ge=1, le=100),
):
    ...
```

---

# 12. Response Model Standards

Every production endpoint should define an appropriate response model.

Example:

```python
@router.get(
    "/{project_id}",
    response_model=ProjectResponse,
)
async def get_project(project_id: str):
    ...
```

Response models provide:

```text
Validation
+
Documentation
+
Consistent API Contracts
+
Controlled Data Exposure
```

Do not return unrestricted database objects directly.

---

# 13. Response Status Codes

Use appropriate HTTP status codes.

Common examples:

```text
200 OK
201 Created
202 Accepted
204 No Content
400 Bad Request
401 Unauthorized
403 Forbidden
404 Not Found
409 Conflict
422 Unprocessable Entity
429 Too Many Requests
500 Internal Server Error
```

The status code must accurately represent the operation result.

---

# 14. Error Handling

Use consistent API error responses.

Example:

```json
{
  "error": {
    "code": "PROJECT_NOT_FOUND",
    "message": "Project was not found",
    "request_id": "req_123"
  }
}
```

Do not expose:

```text
Stack traces
Database errors
Internal paths
Credentials
Internal implementation details
```

Business-specific exceptions should be converted into appropriate HTTP responses.

---

# 15. Exception Handlers

Use centralized exception handlers where appropriate.

Example:

```python
@app.exception_handler(ProjectNotFoundError)
async def project_not_found_handler(
    request: Request,
    exc: ProjectNotFoundError,
):
    return JSONResponse(
        status_code=404,
        content={
            "error": {
                "code": "PROJECT_NOT_FOUND",
                "message": "Project was not found",
            }
        },
    )
```

Avoid duplicating error-response logic across every route.

---

# 16. Dependency Injection

Use FastAPI dependency injection for shared dependencies.

Examples:

```text
Database Session
Authentication
Authorization
Current User
Services
Repositories
Configuration
External Clients
```

Example:

```python
@router.get("/{project_id}")
async def get_project(
    project_id: str,
    service: ProjectService = Depends(get_project_service),
):
    return await service.get_project(project_id)
```

Dependencies should be reusable and testable.

---

# 17. Authentication

Protected endpoints must implement authentication.

Example:

```text
Request
 ↓
Authentication
 ↓
Authorization
 ↓
Route
```

Authentication mechanisms may include:

```text
JWT
OAuth2
OIDC
API Keys
```

depending on project requirements.

Never implement authentication using custom insecure mechanisms when a standard mechanism is available.

---

# 18. Authorization

Authentication and authorization are separate concerns.

Authentication answers:

```text
Who are you?
```

Authorization answers:

```text
What are you allowed to do?
```

Implement role or permission checks where required.

Example:

```text
Admin
 ↓
Can deploy production

Developer
 ↓
Can deploy staging

Viewer
 ↓
Read-only
```

Never rely only on frontend authorization.

---

# 19. CORS Standards

Configure CORS explicitly.

Example:

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://example.com"],
    allow_credentials=True,
    allow_methods=["GET", "POST"],
    allow_headers=["Authorization", "Content-Type"],
)
```

Avoid unrestricted production configuration such as:

```python
allow_origins=["*"]
```

unless explicitly required and reviewed.

---

# 20. Middleware Standards

Middleware should be used for cross-cutting concerns.

Examples:

```text
Request ID
Logging
CORS
Security Headers
Metrics
Tracing
```

Do not place business logic inside middleware.

---

# 21. Request ID and Correlation

Every request should have a traceable request ID.

Example:

```text
Client
 ↓
Request ID
 ↓
FastAPI
 ↓
Service
 ↓
Repository
 ↓
External Service
```

The request ID should be included in relevant logs and error responses.

---

# 22. Logging Standards

Use Python logging rather than `print()`.

Example:

```python
logger.info(
    "Project created",
    extra={"project_id": project_id},
)
```

Never log:

```text
Passwords
JWT tokens
API keys
Authorization headers
Private keys
Sensitive personal data
```

Use structured logging where supported.

---

# 23. Database Integration

Database access must remain outside route handlers.

Preferred:

```text
FastAPI Route
      ↓
Service
      ↓
Repository
      ↓
SQLAlchemy
      ↓
PostgreSQL
```

Use dependency injection for database sessions.

Database connections must be properly created, reused, and released according to the selected database architecture.

---

# 24. Async Standards

Use asynchronous endpoints when performing I/O-bound operations with async-compatible libraries.

Example:

```python
@router.get("/{project_id}")
async def get_project(project_id: str):
    return await service.get_project(project_id)
```

Do not perform blocking operations inside async endpoints.

Avoid mixing synchronous and asynchronous database or HTTP clients incorrectly.

---

# 25. External API Calls

External service calls must have:

```text
Timeout
+
Error Handling
+
Response Validation
+
Retry Strategy
+
Logging
```

Example:

```python
async with httpx.AsyncClient(timeout=30.0) as client:
    response = await client.get(url)
    response.raise_for_status()
```

Never allow external requests to wait indefinitely.

---

# 26. Background Tasks

FastAPI requests should not remain open for long-running operations.

Examples:

```text
Code Generation
Docker Build
Testing
Terraform Deployment
RAG Ingestion
Agent Execution
```

For lightweight operations, FastAPI background tasks may be appropriate.

For reliable long-running jobs, use a dedicated worker or task queue.

Recommended architecture:

```text
API Request
    ↓
Create Job
    ↓
Return Job ID
    ↓
Worker
    ↓
Execute Job
    ↓
Update Job Status
```

---

# 27. Long-Running Agent Jobs

Agentic SDLC operations should use asynchronous job processing.

Example:

```text
POST /api/v1/projects
        ↓
Create Project
        ↓
POST /api/v1/jobs
        ↓
Return job_id
        ↓
Agent Workflow
        ↓
Checkpoint State
        ↓
Update Status
```

Example response:

```json
{
  "job_id": "job_123",
  "status": "queued"
}
```

Clients should be able to query job status.

Example:

```text
GET /api/v1/jobs/{job_id}
```

---

# 28. Pagination

Collection endpoints must support pagination when the result set can become large.

Example:

```text
GET /api/v1/projects?page=1&page_size=20
```

Limit maximum page size.

Example:

```python
page_size: int = Query(
    default=20,
    ge=1,
    le=100,
)
```

Use cursor-based pagination where appropriate.

Never return unlimited database records.

---

# 29. Filtering and Sorting

Filtering and sorting parameters must be explicitly defined.

Example:

```text
GET /api/v1/projects?
    status=active&
    sort_by=created_at&
    order=desc
```

Only allow approved fields for sorting.

Never directly inject client-provided values into SQL queries.

---

# 30. File Uploads

File uploads must be validated.

Validate:

```text
File Size
File Type
Extension
Filename
Content
```

Example:

```python
from fastapi import UploadFile
```

Never trust client-provided filenames or content types.

Store uploaded files using safe generated identifiers where appropriate.

---

# 31. API Documentation

FastAPI OpenAPI documentation must accurately represent the API.

Document:

```text
Endpoints
Request Models
Response Models
Parameters
Authentication
Errors
Status Codes
```

Use descriptions and examples where they improve API usability.

Do not allow documentation to become inconsistent with implementation.

---

# 32. Health Checks

Production services should expose health endpoints.

Example:

```text
GET /health
```

Recommended separation:

```text
/health
/readiness
```

Health checks should be lightweight.

Readiness checks may verify required dependencies such as:

```text
Database
Required External Services
Message Queue
```

Do not expose sensitive infrastructure details.

---

# 33. API Security

FastAPI applications must protect against:

```text
SQL Injection
Command Injection
Path Traversal
Broken Authentication
Broken Authorization
Insecure File Uploads
Sensitive Data Exposure
Excessive Requests
Unsafe Deserialization
```

Validate all external input.

Never execute arbitrary user-provided commands.

---

# 34. Rate Limiting

Public or sensitive endpoints should implement rate limiting where required.

Especially protect:

```text
Authentication
Password/Token Operations
Expensive AI Operations
Deployment Operations
Public APIs
```

The rate-limiting mechanism must be appropriate for the deployment architecture.

---

# 35. Secrets Management

Secrets must never be hardcoded.

Bad:

```python
OPENAI_API_KEY = "sk-..."
```

Good:

```python
from pydantic_settings import BaseSettings


class Settings(BaseSettings):
    openai_api_key: str
```

Use:

```text
Environment Variables
Secret Managers
Secure CI/CD Credentials
```

Never return secrets through API responses.

---

# 36. LLM API Standards

LLM calls must be isolated behind a service abstraction.

Example:

```python
class LLMService:

    async def generate(
        self,
        prompt: str,
    ) -> str:
        ...
```

The API layer should not directly contain provider-specific LLM logic.

LLM operations must define:

```text
Timeout
Retry Policy
Token Limits
Error Handling
Response Validation
Logging
```

---

# 37. RAG API Standards

RAG endpoints should clearly separate:

```text
Document Ingestion
 ↓
Chunking
 ↓
Embedding
 ↓
Vector Storage
 ↓
Retrieval
 ↓
Generation
```

Example APIs:

```text
POST /api/v1/knowledge
GET  /api/v1/knowledge
DELETE /api/v1/knowledge/{document_id}
POST /api/v1/query
```

Retrieved content must be treated as untrusted data.

---

# 38. Agent API Standards

Agent execution APIs should expose controlled operations.

Example:

```text
POST /api/v1/agents/run
GET  /api/v1/jobs/{job_id}
POST /api/v1/jobs/{job_id}/cancel
```

Agent endpoints must not expose unrestricted tool execution.

Tool access must be:

```text
Authorized
Validated
Audited
Rate Limited
```

---

# 39. Idempotency

Operations that may be retried must support idempotency where appropriate.

Especially:

```text
Deployment
Infrastructure Creation
Payment-like Operations
External Resource Creation
Agent Job Submission
```

Use:

```text
Idempotency Keys
State Checks
Unique Constraints
```

to prevent duplicate operations.

```text
Unit Tests

API Tests
E2E Tests
```

# 41. API Test Example

Example:

```python
def test_create_project(client):
    response = client.post(
        "/api/v1/projects",
        json={
            "name": "Test Project"
        },
    )

    assert response.status_code == 201
```

Tests should validate both:

```text
Status Code
+
Response Body
```

---

# 42. Dependency Overrides in Tests

FastAPI dependency overrides should be used to isolate tests.

Example:

```python
app.dependency_overrides[
    get_project_service
] = get_test_project_service
```

This allows:

```text
Real Database
      ↓
Test Dependency
      ↓
Mock/Fake Service
```

without changing production code.

---

# 43. Performance Standards

Avoid unnecessary work inside request handlers.

Consider:

```text
Database Query Optimization
Connection Pooling
Caching
Pagination
Async I/O
Background Jobs
Response Compression
```

Expensive operations should be moved to background workers where appropriate.

---

# 44. Caching

Use caching for frequently accessed data when appropriate.

Potential technologies:

```text
Redis
In-memory cache
CDN
```

Caching must define:

```text
TTL
Invalidation Strategy
Consistency Requirements
```

Do not cache sensitive data without appropriate security controls.

---

# 45. Graceful Shutdown

Applications must gracefully release resources during shutdown.

Examples:

```text
Database Connections
HTTP Clients
Workers
Message Consumers
Background Tasks
```

Use FastAPI lifespan mechanisms where appropriate.

---

# 46. Environment Separation

Support separate configurations for:

```text
Development
Staging
Production
```

Never use production credentials in development or tests.

Environment-specific behavior must be controlled through configuration.

The Backend Agent must ensure every FastAPI application follows these core standards:

```text

    → Versioned, REST-oriented, resource-based endpoints

    → Pydantic request/response schemas

Architecture
    → Thin Routes
    → Service Layer
    → Repository Layer
    → Database

Security
    → Authentication + Authorization
    → Secure CORS
    → Secret Management
    → Input Validation
    → Rate Limiting where required
    → No arbitrary command execution

Reliability
    → Explicit timeouts
    → Controlled retries
    → Idempotency
    → Graceful error handling

Performance
    → Async I/O
    → Pagination
    → Caching where appropriate
    → Background workers for long-running operations

Agentic AI
    → Controlled agent execution
    → Isolated LLM integration
    → Secure RAG integration
    → Job-based long-running workflows

Observability
    → Request IDs
    → Structured logging
    → Health/readiness endpoints

Testing
    → Unit Tests
    → Integration Tests
    → API Tests
    → E2E Tests

Quality Gates
    → Formatting
    → Linting
    → Type Checking
    → Tests
    → Security Validation
    → API Contract Validation

Documentation
    → Accurate OpenAPI documentation
    → Request/response schemas
    → Authentication and error documentation
```

**Core Rule:**

> Every generated FastAPI application must be secure, validated, modular, testable, observable, documented, and production-ready.
